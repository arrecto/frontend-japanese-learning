## Tuon

<!-- Shared section: keep identical in pipeline-, backend- and frontend-japanese-learning. -->

Tuon (トゥオン, "to learn" in Romblomanon) is a Japanese pronunciation trainer built on high-variability phonetic
training (HVPT): learners hear the same phrase from many native speakers, so they learn the sound rather than one
voice. The source audio is the JVS corpus (100 speakers). The design has three learning phases, each with its own
color: listening (gold), recording (sakura) and feedback (teal).

| Repo (side by side in `~/dev/`) | Role | Stack |
| --- | --- | --- |
| `pipeline-japanese-learning` | Cuts JVS recordings into phrase clips. Owns the `corpus` schema and the audio in R2. | Python 3, psycopg 3, boto3. Not a git repo yet. |
| `backend-japanese-learning` | HTTP API. Reads `corpus`, owns the `app` schema. | FastAPI, async SQLAlchemy 2.1, Alembic, uv |
| `frontend-japanese-learning` | Web app. | Next.js 16 (App Router), React 19, Tailwind CSS v4 |

Infrastructure:

- **Postgres**: Neon project `misty-surf-33153966`. All three repos point at the `production` branch, so any write
  from any repo hits production data.
- **Audio**: private Cloudflare R2 bucket. Each clip has a `flac` master and an `opus` delivery copy at
  `audio/jvs/<subset>/<utterance_id>/p<NN>/<speaker_id>.<fmt>`. Clients only ever get short-lived presigned URLs.

Cross-repo contracts. Change both sides together:

| Contract | Source of truth | Mirror |
| --- | --- | --- |
| `corpus` schema | pipeline `db/migrations/*.sql` | backend `app/models/corpus.py` (`tests/test_models.py` checks it against the live DB) |
| API response shapes | backend `app/schemas/corpus.py` | frontend `src/types/corpus.ts` (by hand) |
| DB and R2 credentials | pipeline `.env` | backend `.env` (`DATABASE_URL`, `S3_API_URL`, `S3_ACCOUNT_KEY`, `S3_ACCESS_KEY`) |

## Handoffs (required)

<!-- Shared section: keep identical in pipeline-, backend- and frontend-japanese-learning. -->

Handoffs carry work between sessions and agents. They live in `docs/handoffs/`, one Markdown file per milestone,
named `YYYY-MM-DD-<short-slug>.md`. `docs/handoffs/README.md` holds the index and the template.

Before starting work:

1. Read the newest handoff here, and in sibling repos the task touches.
2. Follow its decisions and next steps unless the user says otherwise. If the code disagrees with a handoff, trust
   the code and tell the user.

At every major milestone, write a handoff before moving on, and before ending a session with work in flight. A
major milestone is any of:

- a feature working end to end
- a change to the database schema or an API contract
- a new service, integration or significant dependency
- a design-system or architecture decision
- the user changing direction

Rules:

- Write one in every repo the milestone changed, each about that repo's part, linking the others under "Related".
- Follow the template and add the file to the index in `docs/handoffs/README.md`.
- Record only what you verified, and how. List what you didn't verify.
- Don't rewrite old handoffs. A newer one supersedes them; only fix factual errors.
- Never write secrets. Env var names are fine, values aren't.

## This repo: frontend-japanese-learning

@AGENTS.md

`AGENTS.md` is generated by `next dev`: read the docs in `node_modules/next/dist/docs/` before using Next.js APIs.
This is Next.js 16 with `cacheComponents` and `partialPrefetching` on.

```bash
nvm use                 # Node 24 (.nvmrc)
npm install             # project .npmrc pins the public registry (the global ~/.npmrc points at a work registry)
cp .env.example .env.local
npm run dev             # http://localhost:3000, needs the backend on :8000 for live data
npm run lint && npx tsc --noEmit && npm run build
```

Layout:

```
src/
  app/layout.tsx    Root layout; loads the four fonts with next/font
  app/globals.css   All design tokens (Tailwind v4 @theme)
  app/page.tsx      Placeholder home page with an API status check
  lib/config.ts     API_URL (NEXT_PUBLIC_API_URL, default http://localhost:8000/api/v1)
  lib/api.ts        apiGet<T>() and ApiError
  types/corpus.ts   API types, mirroring backend app/schemas/corpus.py
```

Design tokens (`src/app/globals.css`, documented in README.md). Dark theme only.

- **Use semantic tokens**, named for their role:
  - backgrounds: `bg-base`, `bg-surface`, `bg-surface-raised`
  - text: `text-primary`, `text-secondary`, `text-muted`
  - borders: `border-default` (the default for every border), `border-subtle`
  - accents and states, with any color utility: `accent`, `accent-deep`, `listening`, `recording`, `feedback`,
    `correct`, `weak`, `complete`
  - gradients: `bg-canvas`, `bg-canvas-deep`
- **Palette scales** (`night`, `sand`, `gold`, `teal`, `sakura`, 50 to 950, plus `void`) are for cases the
  semantic tokens don't cover. Never hard-code hex values in components.
- **Color encodes learning phase, not decoration**: gold = listening, sakura = recording, teal = feedback.
- **Fonts**: `font-display` (Fraunces, headlines), `font-sans` (Manrope, default UI), `font-jp` (Shippori Mincho,
  all kana and kanji, with `lang="ja"`), `font-mono` (JetBrains Mono, IPA, timers, scores).
- The source design is "Hoshibi design tokens v0.1" (`~/Downloads/hoshibi_design_tokens.html`). Tokens were renamed
  for readability (`--ink` became `text-primary`, and so on), and the full mapping is in the comments in
  `globals.css`.

Conventions:

- Style with Tailwind utilities. No CSS modules or inline style objects unless Tailwind can't express it.
- Server Components by default. Fetch through `apiGet`. Request presigned audio URLs shortly before playback and
  never cache them (they expire after about 5 minutes).
- **Lint gotcha**: `react-hooks/error-boundaries` rejects JSX built inside `try/catch`. Catch first, then render.
